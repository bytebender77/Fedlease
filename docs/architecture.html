FedLEASE-FinBERT · Federated Adaptive LoRA Experts for Financial NLP

System architecture · clustered LoRA-MoE · adaptive top-M routing · cluster-wise FedAvg · ProsusAI/FinBERT backbone
PyTorch HuggingFace LoRA r=4 N=10 clients T=25 rounds M_max=8 PhraseBank + Twitter

1High-Level System Architecture

Two heterogeneous financial-text corpora are partitioned across 10 federated clients. Each client trains a private LoRA-MoE adapter over a frozen FinBERT backbone; only assigned-expert LoRA updates and router gates cross the network. The coordinator hosts five logical engines that drive similarity, clustering, expert allocation, cluster-wise aggregation, and experiment monitoring.

2Phase A · Warmup Workflow

Before clustering can happen, each client independently fine-tunes a single LoRA pair (q, v projections) on its local data for warmup_epochs = 3. The trained B matrices — small, low-rank, task-conditioned — are uploaded to the server, where they will form the input to the similarity engine.

3Clustering & Expert-Allocation Workflow

The B-matrix distance matrix is fed into a sweep over candidate cluster counts k ∈ [M_min, M_max]. Silhouette is maximised at k = M*, which fixes both the number of experts and the assignment c(i) of each client to a cluster. The initialisation of each cluster expert (Eq. 3) is the mean of its members' warmup LoRA pairs.

4Adaptive Top-M Routing (G ∈ R(2M−1)×d, with assigned-expert guarantee)

The single most novel component. Output dimension 2M − 1 (not 2M, not M) is the minimum that structurally guarantees the client's assigned expert participates in the top-M for every input — proven combinatorially below. Worked example: M = 3, assigned expert E_0.

5Phase B · Federated Training Round (synchronous protocol, T = 25 rounds)

A single round of the iterative training phase: broadcast → local LoRA-MoE training → upload of only the assigned expert + router → cluster-wise weighted averaging. Trainable surface ≈ 0.27% of FinBERT; upload per client per round ≈ 600 KB at fp32.

6LoRA Integration inside the FinBERT Transformer Layer

Zoom into one of FinBERT's 12 transformer layers. The frozen 768×768 query and value projections are augmented in parallel with a set of M rank-r LoRA experts. The per-input router (Diagram 4) selects M of them with weights ω̂. The full update equation is shown bottom-centre.

7End-to-End Data Flow · A Single Inference

Trace one example from raw text to sentiment prediction. The router branches off the [CLS] embedding to compute top-M routing once; the same decision is injected into every LoRA-MoE module of the encoder via the _routing_weights attribute.

8Communication Payload & Cluster-Wise Aggregation

The communication-aggregation closeup. Each client uploads only its assigned-expert LoRA pair, its router gate, and its dataset size. The server bins uploads by cluster, performs weighted averaging within each cluster, FedAvg's the classifier head globally, and broadcasts the updated expert bank back. No cross-cluster averaging ⇒ negative-transfer term vanishes.

Data & Federation

LoRA · Routing · MoE

  • • FinBERT frozen (110 M params)
  • • LoRA rank r = 4, α = 8 on q, v projections
  • • Adaptive top-M router · 2M − 1 output
  • • Assigned-expert guarantee (proven)
  • • ≈ 0.27% of model trainable

Server & Aggregation

  • • B-matrix cosine similarity (Eq. 2)
  • • Agglomerative · average linkage
  • • M* = argmax silhouette · k ∈ [2, 8]
  • • Expert init = intra-cluster mean (Eq. 3)
  • • Cluster-wise weighted FedAvg per round
